

# testcase.yml-CaseInfo-Object[] []

如何将从 `testcase.yml` 文件加载的测试用例数据转换为 `CaseInfo` 对象，并最终将其组织成 `Object[][]` 格式供 TestNG 使用。

### **1. `testcase.yml` 文件格式**

我们假设 `testcase.yml` 文件包含了一些测试用例的基础信息，比如：

```
testCases:
  - caseId: 1
    desc: "登录"
    type: POST
    url: "/admin/login"
    params: "{\"username\":\"test\",\"password\":\"123456\"}"
    contentType: "application/json"
    expectedResult: "{\"code\": 200, \"msg\": \"操作成功\"}"
  
  - caseId: 2
    desc: "登出"
    type: POST
    url: "/admin/logout"
    params: "{}"
    contentType: "application/json"
    expectedResult: "{\"code\": 200, \"msg\": \"登出成功\"}"
```

这里，`testCases` 是一个包含多个测试用例的列表，每个测试用例有：

- `caseId`: 用例ID
- `desc`: 描述
- `type`: 请求方法（`POST`、`GET` 等）
- `url`: 请求路径
- `params`: 请求参数（如 JSON 格式）
- `contentType`: 请求内容类型
- `expectedResult`: 期望响应结果

### **2. 将每个测试用例转换为 `CaseInfo` 对象**

从 `testcase.yml` 文件中，我们需要提取每个测试用例的数据，并将其转换为 `CaseInfo` 对象。`CaseInfo` 是一个包含以上字段的简单类，主要负责存储每个测试用例的基本信息。

**示例**:

- `caseId` 转换为 `CaseInfo` 的 `caseId` 字段
- `desc` 转换为 `CaseInfo` 的 `desc` 字段
- `type` 转换为 `CaseInfo` 的 `type` 字段
- `url` 转换为 `CaseInfo` 的 `url` 字段
- `params` 转换为 `CaseInfo` 的 `params` 字段
- `contentType` 转换为 `CaseInfo` 的 `contentType` 字段
- `expectedResult` 转换为 `CaseInfo` 的 `expectedResult` 字段

### **3. 将多个 `CaseInfo` 对象组织成 `Object[][]` 格式**

`Object[][]` 是 TestNG `@DataProvider` 所需要的数据格式。我们将每个 `CaseInfo` 对象放入这个二维数组中，使得 TestNG 可以依次使用每个 `CaseInfo` 对象执行测试。

假设我们有 2 个测试用例，那么 `Object[][]` 的结构会如下：

- `data[0][0]` 存储第一个 `CaseInfo` 对象，代表登录接口。
- `data[1][0]` 存储第二个 `CaseInfo` 对象，代表登出接口。

### **4. `@DataProvider` 使用**

TestNG 提供了 `@DataProvider` 注解来提供测试数据，`Object[][]` 格式的数据会作为测试方法的输入参数。每次运行测试时，TestNG 会从 `Object[][]` 数组中取出一个 `CaseInfo` 对象，传递给测试方法，进行数据驱动的测试。

### **总结**

- **数据加载**: 从 `testcase.yml` 文件中加载所有测试用例的数据。
- **数据转换**: 将 YAML 数据转换为 `CaseInfo` 对象。
- **数据提供**: 将 `CaseInfo` 对象放入 `Object[][]` 数组，供 TestNG 测试方法使用。

这样，你就可以将 `testcase.yml` 文件中的测试用例数据动态加载并用于 TestNG 的数据驱动测试，而不需要手动输入每个测试用例的数据。
