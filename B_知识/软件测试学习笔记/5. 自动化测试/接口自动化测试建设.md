# 接口自动化测试建设

## 项目介绍

该项目是 **[图灵商城后台管理系统](http://115.159.42.77/#/home)**，使用 **Swagger 2.0** 定义了项目的 API 接口文档，提供了一系列功能接口，主要涉及后台用户管理。接口包括用户登录、登出、注册、信息更新、角色分配等操作。

### 主要功能：

1. **后台用户管理（UmsAdminController）**：
   - 登录
   - 登出
   - 注册
   - 删除用户
   - 修改用户信息
   - 角色分配

## 接口自动化测试

为了确保后台管理系统的 API 接口在各种情况下均能正常工作，接下来将进行接口自动化测试。以下是整个自动化测试的建设过程：

---

### 一、需求分析与规划

#### 目标：

1. **功能性测试**：验证各个接口功能是否正常，包括正确的响应结果、状态码等。
2. **安全性测试**：确保系统对未授权或无效的请求进行正确的权限验证。
3. **异常测试**：验证接口能正确处理边界值、空值或非法输入。
4. **性能测试**：测试接口的响应时间，确保系统的高效性。

#### 测试接口：

根据 **Swagger** 文档，以下接口是需要测试的目标：

- **用户登录** (`/admin/login`)
- **获取当前用户信息** (`/admin/info`)
- **用户列表** (`/admin/list`)
- **删除用户** (`/admin/delete/{id}`)
- **用户注册** (`/admin/register`)
- **修改用户信息** (`/admin/update/{id}`)
- **角色分配** (`/admin/role/update`)

---

### 二、工具选择与框架搭建

#### 选择工具与框架：

1. **Rest-Assured**：用于发送 HTTP 请求、验证响应数据，并进行断言。
2. **TestNG**：用于组织测试用例，支持并行执行、数据驱动测试，并生成详细的测试报告。
3. **Allure**：生成美观且详细的 HTML 测试报告。
4. **Maven**：用于管理项目的依赖和构建过程。
5. **Jenkins**: 实现CICD。

### 四、编写自动化测试用例

#### 1. 设计测试用例
##### 思路
- 自动从 **Swagger** 文件中提取信息，并动态生成符合您需求的 **YAML** 文件结构，我们需要通过代码解析 **Swagger** 文件，提取出接口的基本信息（如路径、请求方法、请求体、响应等），然后构建符合以下结构的 **YAML** 文件。
##### 目标

通过解析原始的 **Swagger** 文件（如 YAML 格式的 OpenAPI 文档），动态提取：
- 接口描述（登录）
    
- 请求方法（GET、POST 等）
    
- 请求路径
    
- 请求参数（如路径参数、查询参数）
    
- 请求体（如果有）
    
- 响应状态码与响应体（期望的返回内容）
    

然后将这些信息转化为符合以下结构的 **YAML** 文件：

```yaml
api_tests:
  - caseId: "1"
    method: "POST"
    url: "/admin/login"
    desc: "登录"
    params:
      - name: "username"
        type: "string"
        required: true
      - name: "password"
        type: "string"
        required: true
    contentType: "application/json"
    expectedResult:
      responseBody:
        code: 200
        message: "登录成功"
    
```

### 五、执行与报告生成

#### 1. 执行自动化测试

- 使用 **TestNG** 执行测试，或者通过 **Maven** 命令：

  ```
  mvn clean test
  ```

#### 2. 生成测试报告

执行测试后，可以生成 **TestNG** 和 **Allure** 测试报告。

- **TestNG** 报告：默认生成在 `target/test-classes/testng` 目录。

- **Allure** 报告：通过以下命令生成：

  ```
  mvn clean test
  mvn allure:serve
  ```

------

### 六、集成 CI/CD

将接口自动化测试集成到 **CI/CD** 流程中，确保每次代码提交后自动执行测试。

#### 1. Jenkins 集成示例

- 在 Jenkins 中创建一个 **Maven** 构建任务，设置构建命令 `mvn clean test`。
- 在构建完成后，可以查看 **TestNG** 或 **Allure** 报告。

------

### 七、维护与扩展

- **新增接口测试**：根据需求编写新的接口测试用例。
- **回归测试**：确保修改不会破坏现有功能。
- **数据驱动测试**：通过 **TestNG** 的 **@DataProvider** 支持多数据集的测试。
- **Mock 测试**：使用 **WireMock** 或 **MockServer** 来模拟外部接口。

------

### 总结

通过以上步骤，您可以使用 **Rest-Assured** 和 **TestNG** 来进行接口自动化测试，涵盖从接口测试用例设计、测试代码编写、测试执行、报告生成，到 CI/CD 集成的整个过程。
