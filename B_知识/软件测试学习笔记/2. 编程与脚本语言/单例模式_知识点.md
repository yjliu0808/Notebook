# 单例模式 (Singleton Pattern)

## 1. 单例模式概述

单例模式（Singleton Pattern）是一种设计模式，确保某个类只有 **一个实例**，并且提供一个 **全局访问点** 来访问该实例。该模式主要用于 **控制类的实例化过程**，避免类被多次实例化，节省资源。

单例模式常用于以下场景：
- 配置管理
- 数据库连接池
- 日志管理
- 应用程序级别的全局对象

## 2. 单例模式的核心原理

单例模式的核心原理包括以下几点：

1. **唯一性**：单例模式保证了一个类在整个程序中只有一个实例。
2. **全局访问**：通过静态方法提供对实例的全局访问，外部无法直接通过构造方法来创建实例。
3. **延迟加载**：实例只会在第一次需要时被创建，避免程序启动时就占用资源（懒汉式）。后续调用会直接返回已创建的实例。

## 3. 单例模式的结构

- **静态变量**：存储类的唯一实例，保证全局只有一个实例。
- **私有构造函数**：防止外部直接通过 `new` 创建实例。
- **静态方法 `getInstance()`**：用于访问唯一实例，确保第一次使用时才创建实例。

## 4. 单例模式实现示例

### 基本实现

```java
public class Singleton {

    // 1. 静态变量存储唯一实例
    private static Singleton instance;

    // 2. 私有构造函数，防止外部直接实例化
    private Singleton() {
        // 初始化操作
    }

    // 3. 提供公共静态方法获取实例
    public static Singleton getInstance() {
        // 4. 第一次调用时实例化对象
        if (instance == null) {
            synchronized (Singleton.class) {
                // 双重检查锁定，确保线程安全
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;  // 返回唯一实例
    }

    // 5. 其他公共方法
    public void doSomething() {
        System.out.println("Singleton instance is doing something!");
    }
}
```

### 代码说明：

- **私有构造函数**：确保外部无法通过 `new` 创建实例。
- **静态变量 `instance`**：保存唯一实例，保证全局只创建一个实例。
- **`getInstance()` 方法**：用于获取唯一实例，确保第一次使用时才创建实例，后续的调用直接返回已存在的实例。

## 5. 线程安全的实现

在多线程环境中，我们需要保证 **线程安全**。可以通过 `synchronized` 关键字来确保同步。

### 双重检查锁定实现（提高性能）

```java
public class Singleton {

    private static volatile Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

### 解释：

- **`volatile` 关键字**：确保 `instance` 变量的修改对所有线程可见，避免出现线程缓存的问题。
- **双重检查锁定**：第一次检查 `instance` 是否为空，如果为空，则加锁；加锁后再检查一次，避免在多线程环境下每次调用 `getInstance()` 都加锁，从而提高性能。

## 6. 封装为公共方法的单例模式

为了简化代码调用，可以将获取单例实例的逻辑封装成公共方法。所有需要访问单例的代码都通过调用该方法来获取实例。

### 示例代码：

```java
public class Singleton {

    private static Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }

    public void doSomething() {
        System.out.println("Singleton instance is doing something!");
    }
}
```

### 使用方法：

```java
public class Main {

    public static void main(String[] args) {
        // 获取单例实例
        Singleton singleton1 = Singleton.getInstance();
        singleton1.doSomething();

        // 再次获取同一个实例
        Singleton singleton2 = Singleton.getInstance();
        singleton2.doSomething();

        // 检查两个实例是否相同
        System.out.println(singleton1 == singleton2);  // 输出 true
    }
}
```

### 输出结果：

```
Singleton instance is doing something!
Singleton instance is doing something!
true
```

## 7. 单例模式的优缺点

### 优点：

- **节省资源**：只创建一个实例，避免了重复创建带来的性能消耗。
- **全局共享**：适用于需要全局共享资源的场景，如配置文件管理、日志管理、数据库连接池等。
- **延迟加载**：只有在第一次使用时创建实例，避免了在应用启动时就占用资源。

### 缺点：

- **全局状态管理**：单例模式引入了全局状态，可能会导致状态难以管理，尤其是在多线程环境下。
- **难以测试**：由于单例模式的实例是静态的，测试时难以模拟或替换该实例。
- **多线程问题**：如果没有正确处理同步，可能会导致多个线程同时创建多个实例的问题。

## 8. 使用场景

单例模式适用于以下场景：

- **配置文件管理**：当需要一个全局共享的配置文件时。
- **数据库连接池**：在整个应用中，数据库连接池只需要一个实例来共享数据库连接。
- **日志管理**：全局共享一个日志对象，以便在多个类中记录日志。

## 9. 小结

单例模式通过 **静态变量** 和 **静态方法**，确保了类在整个程序生命周期中只有一个实例，并且提供了一个全局访问点。单例模式非常适用于一些需要全局共享的对象，如配置管理、数据库连接池等。通过懒汉式和饿汉式的实现方式，可以根据实际需求灵活地实现单例模式。
